# 变更与编排

## 从方案到执行

查询/咨询/澄清不产生写授权。用户已经明确要求执行具体变更时，核对参数和当前状态，
在现有授权内继续；尚不明确的关键目标值先澄清。不设置一律二次确认的额外门槛。
CLI 的安全策略仍按 `volcengine-cli` 处理：被拒绝或要求确认不能通过另一个工具绕过。

计划至少包含：目标及地域、当前值→目标值、受影响对象、执行前检查、验证方法、
回退可行性和未覆盖风险。保留私有操作 ledger，记录任务和资源标识，不记录凭证。
API 名称不推导可用参数；不假定所有操作支持 DryRun、ClientToken 或相同状态枚举。

## 常见决策

| 场景 | 执行前 | 完成证据 / 回退边界 |
|---|---|---|
| 白名单 | 查列表及实例关联；确定新增/删除/覆盖和来源 IP/CIDR；共享白名单还影响哪些实例 | 回查规则与关联；保留原规则，不以全网放通替代解决问题 |
| 参数/模板 | 查当前值、允许范围、是否需重启、模板影响对象 | 回查请求参数，不只看Running；按原值显式回退 |
| 容量/分片/节点变更 | 明确是哪一维、单位、目标值；核验版本、限制、容量与负载 | 任务终态 + 属性达成；缩容不保证随时可用，不把内存使用变化当规格变化 |
| 版本升级 | 明确大/小版本、兼容与维护窗口；查适用升级路径 | 查询版本和应用兼容性；不承诺原地降级 |
| 手动备份 | 查备份策略、实例状态及所需权限，明确备份范围 | 备份完成记录而非仅请求成功；不额外启用PITR或更改策略 |
| 恢复 | 确认备份归属、时间、源/目标及数据覆盖语义 | 任务完成 + 目标数据校验；恢复到原实例和新建实例路径不可混用 |
| 切换/演练 | 明确主从/蓝绿/应用切换是哪一种、流量范围、窗口和依赖 | 控制面状态 + 客户端验证；不能只凭地址存在声称业务成功 |

恢复尤其要按选定 API 的当前文档确认行为。
[API 列表](https://docs.volcengine.com/docs/cache/api-overview?lang=zh) 将
`RestoreDBInstance` 描述为恢复到原实例；不要从用户提供第二台实例就假定可以覆盖该目标，
也不要一概断言恢复只能新建实例。先核验备份集恢复、新实例创建及蓝绿部署各自的契约。

## 跨产品方案

应用接入/蓝绿/恢复演练区分：Redis 源端、Redis 目标端、应用/ECS、网络、安全与数据。
每个依赖记录已有标识、可查询事实、待提供信息和阻断状态。
用户仅要求方案时交付步骤和验收点，不创建应用服务器或修改流量。
对已授权执行：先验证前置依赖，再提交当前阶段操作，取得完成证据后推进；
任一步阻断就返回已完成/未完成和资源清单，不将部分成功包装成端到端成功。

两台空白同版本实例不能证明完成蓝绿升级，空备份清单不能证明恢复验证通过。
验证数据一致性需要用户允许的测试数据、校验方法及客户端，不能凭 Running 推断。

## 基线与清理

共享写实例串行使用；先采集对应字段基线，执行后按已授权清理范围恢复并回查。
回退失败阻断后续依赖该状态的用例；真实版本升级、删除或覆盖数据需另行恢复策略。
实例重建后的 ID/地址必须回填执行配置，不能继续使用旧绑定。
`terraform plan -refresh-only` 只用于观测漂移，不执行 apply 来“自动修复”未知变更。
