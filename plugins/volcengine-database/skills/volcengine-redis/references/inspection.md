# 巡检与治理

## 一次巡检

按用户实例清单或明确项目确定范围，分页盘点后逐实例取证。多地域逐地域记录，
无法访问的实例不从分母消失。单次巡检不隐含创建定时任务、告警规则或自动修复。
执行前列必要数据源及查询预算；达到预算标为部分完成，保留续查范围。

| 维度 | 所需证据 | 交付 |
|---|---|---|
| 可用性 | 当前状态、异常任务、相关事件、连接与错误趋势 | 当前异常与历史异常分开，关联时间和影响 |
| 容量 | 规格、内存/连接/带宽、分片差异、增长趋势 | 当前余量、持续压力与预测假设；短窗口不外推长期结论 |
| 性能 | CPU/QPS/延迟、慢日志、大/热 Key | 尖峰、长尾和热点候选，给证据与建议验证 |
| 访问安全 | 公开白名单、网络与账号/SSL配置（权限允许） | 具体暴露风险，不输出凭证，不自动更改访问规则 |
| 备份与恢复 | 备份策略、最近成功备份、相关任务 | 覆盖与时间；存在备份不等于已验证恢复，不自行演练 |
| 成本与治理 | 真实规格/使用趋势、适用价格或账单权限 | 标识闲置候选和容量优化方案；不凭低使用率自动缩容或编造节省金额 |

阈值优先使用用户 SLO、已配置告警或公开规格限额，注明来源、单位、持续时间与采样粒度。
缺阈值时给出待确认的建议阈值，不称为官方标准。孤立高点与持续超限分开；
无数据为 unknown，部分分页为 partial，无权限为 denied，查询错误为 error。
只有证据覆盖并符合明确标准才能将该检查项标为通过，不给缺项实例颁发整体健康结论。

## 多实例、治理与复查

逐实例列：地域/目标、检查窗口、风险与证据、缺口、建议、是否需要变更授权。
汇总覆盖数/目标数和各数据源完整性，再按影响、持续性及证据强度排序。
跨产品只沿明确关联资源继续调查，不扫整账号。预算不足先交付已完成检查及缺口。
复杂治理输出分阶段计划：证据与目标 → 小范围试点 → 指标验证 → 扩大/停止 → 回退边界。
自动化策略要定义窗口、阈值、冷却、最大作用范围和停止条件；用户只要方案时不部署。
复查沿相同维度/窗口口径取证；恢复正常只能说明观测窗口内恢复，不能证明永不复发。
