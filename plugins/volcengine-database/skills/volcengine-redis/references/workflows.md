# 场景判断

## 产品知识、兼容与成本

用户询问概念而未要求核对实例时直接查官方规则，不强求实例 ID。
已有实例且问题依赖版本/架构时查询实际配置，再核对相应文档：
[官方入口](https://docs.volcengine.com/docs/cache?lang=zh) 中的实例规格、命令支持、
命令限制、参数支持、计费项与价格。不要将开源 Redis 的支持范围直接当成托管产品承诺。

将结论分为默认支持、需申请/开白、当前版本不支持、尚未核实。
开白资格、账号配额、库存与实际报价都不是文档通用能力可以证明的事实。
成本问题需要计费方式、当前规格、观察周期、利用率以及实际价格/账单证据；
没有价格数据只给计算口径和缺口，不编造金额、优惠或节省比例。
低用量不自动授权缩容，也不证明该容量能承受峰值。

## 盘点和漂移

先明确是某实例详情还是整个项目清单，避免为了单实例问题拉全部地域。
把分片数、每分片内存、每分片节点数和节点拓扑分别呈现；节点总数要由拓扑或有依据的
计算得出，不能把 NodeNumber 当成全实例节点总数。数量和单位以所用 API 契约为准。

两次快照比较时固定同一 Region、实例集合/项目和权限上下文。分别列出配置变化、
状态变化与用量变化。`Capacity.Used` 增长本身不是扩容，也不能归因于用户写入 Key。
范围内未命中的 ID 需要进一步核实，不直接标记资源删除。
当前状态与基线一致，不代表期间无操作；历史变更需要任务/操作审计证据。

## 连接、白名单与 SSL

分清控制面 API 调用失败和客户端数据面连接失败。
对后者先取得错误原文、发生时间、访问地址类型、客户端版本/连接模式和来源网络。
可查询的实例状态、地址、VPC、配置自行查询，不反复让用户补充。

沿 DNS → 网络路由/来源 → 白名单/安全组 → TLS → 认证/ACL → Redis 命令兼容性
选择与错误相关的证据，不要求每次遍历整条链。
- Running 只证明实例控制面状态，不证明客户端连通、认证成功或应用正确。
- 同 VPC 不等于链路必通；来源 IP 应来自应用实际出口，不猜用户本机 IP。
- 无公网地址是事实，不能直接认定是故障；开公网不是默认修复。
- TLS/认证错误不通过关闭 SSL、免密或全网白名单绕过。
- 应用/ECS ID、版本或部署位置未给出时明确缺口；不编造跨产品关联。

## 监控、慢日志、大 Key 与热 Key

先固定时间窗（含时区）、实例/节点维度和指标统计周期；相同窗口的证据才能关联。
慢日志与热点列表需要处理分页，并标明采样条件、留存和权限限制。
空集不等于没有性能问题，指标缺点不补 0，没有样本不虚构热点或慢 SQL。

查询已有分析结果和触发分析任务是两类操作。
[CreateKeyScanJob](https://docs.volcengine.com/docs/cache/createkeyscanjob?lang=zh)
会创建异步扫描任务并增加 CPU 负载；不为了补齐查询结果擅自启动扫描。
也不以全库 KEYS、压测、写大 Key 或造故障作为普通排障手段。

## 操作报错与只读排障

取得确切 Action/入口、参数摘要、错误码、RequestId、时间与目标。
当写请求返回超时/未知结果时先查任务和当前状态，不重复发送变配、创建或恢复。
区分已确认原因、待验证假设和还缺的证据；当前状态正常不排除之前发生过故障。
没有错误码/时间时仍可返回可取得的现状并集中列出缺口，不直接编造根因。
