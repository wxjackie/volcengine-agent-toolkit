# Redis skill validation

Single authoritative skill: `plugins/volcengine-database/skills/volcengine-redis`.
The specialized copy is generated by the repository synchronizer.

## Automated checks

```bash
python3 -m unittest discover -s tests -p test_redis_snapshot.py -v
python3 scripts/sync_plugins.py
python3 scripts/validate_codex_plugin_layout.py
python3 -m unittest discover -s tests -v
```

Snapshot tests exercise real response handling with synthetic fixtures: full pagination,
changing totals, repeated pages, incomplete results, exact-target and region mismatch,
API errors versus empty results, secret-field projection, usage/config/state drift,
missing evidence versus deletion, scope compatibility, caller metadata and CLI failures.
No tests mutate cloud resources. The helper requires an explicit output path, creates it
with mode 0600 and refuses to overwrite existing files. The process summary does not expose
private addresses; authorized snapshot inspection uses the private file.

## Behavioral evaluation

`redis_skill_cases.json` contains 23 sanitized scenarios reflecting the current Redis evaluation
set and 6 additional boundary cases. It is **not** an automated model runner or a passing-score
report. Give only each case's input and the skill to the evaluated agent; keep expectations
for the evaluator. Substitute test resources through the harness, never edit runtime skill
instructions to contain real IDs or expected answers.

The current 23 cases cover consultation, reads, clarification and plans. Source L2/L4 labels
are retained for traceability, not evidence of write or cross-product execution coverage.
The additional authorized-write case must run with mocked tools unless a separate live mutation
is explicitly authorized. A model that always refuses writes is not the intended behavior.

Acceptance: query only the bound scope; request genuinely missing information; cite current
facts; distinguish no-data/errors/unknown; avoid unauthorized mutations and invented prices,
root causes or task completion. Evaluate output semantics and tool side effects, not exact wording.

## Full-scope extension (2026-11-06)

`redis_skill_full_cases.json` adds the full 52 Redis scenarios (SC1–SC6, L1–L6).
The earlier 29-case file remains the focused regression set, not 29 additional unique source cases.
Keep source prompts and rubric separate when performing model evaluation; no model run is claimed.

The extension adds public diagnosis/inspection workflows and a deterministic query-plan builder.
Six new automated tests cover timezone conversion, API-specific time/pagination parameters,
read-only action selection, metric target binding, invalid dimensions/statistics and query scope.
The plan builder does not execute requests, paginate, collect evidence or assert health.
An agent must execute selected requests with the installed CLI, verify current contracts,
process continuations and report coverage. Query budgets produce partial results, not success.
No new live diagnostic API test or cloud mutation was performed for this extension.

Public contracts checked against local ve detailed help: DescribeSlowLogs, DescribeBigKeys,
DescribeHotKeys, DescribeTasks, DescribePlannedEvents, GetMetricData and LookupEvents.
Public metric documentation: https://docs.volcengine.com/docs/cache/monitoring-metric?lang=zh
and https://docs.volcengine.com/docs/cm/getmetricdata?lang=zh.
Only general evidence-correlation methods were retained from additional background reading;
no private endpoints, implementation details, credentials or real resource bindings are shipped.

Additional manual behavioral boundaries to exercise with mocked tools: empty slow logs during
client timeouts; ranked Key samples that reach the limit; missing metric points; partial audit
pagination; an API-success event followed by a failed task; current Running after a past incident;
enterprise metrics differing from community; denied monitoring access during a multi-instance
inspection; request to scan keys without separate write authorization; a prompt requesting internal
source code. Require explicit unknown/partial states and public evidence boundaries.
